# Syllabind — Alur Bisnis & Aturan

Dokumen kerja. Ringkasan perilaku aplikasi saat ini + rencana 2 fitur.
Bukan spesifikasi implementasi; langkah saja.

---

## 1. Gambaran aplikasi

- Flutter + SQLite lokal (sqflite). Offline penuh, tanpa akun, tanpa server.
- 4 tab utama (`IndexedStack` di `lib/main.dart`): **Home**, **Academic**, **Library**, **Pengaturan**.
- Bahasa Indonesia/Inggris, tema terang/gelap/sistem, warna aksen — semuanya disimpan di tabel `pengaturan`.
- Sumber data tunggal: `lib/services/`. UI tidak menyentuh SQL langsung.
- Data master: **Mapel** → **Materi (catatan)** / **Tugas** → **Lampiran (gambar/file)**.

### Model & relasi

| Entitas | Tabel | Induk | Hapus |
|---|---|---|---|
| Mapel | `mata_pelajaran` | — | soft delete (`deleted_at`) → Sampah |
| Materi/Catatan | `materi_pembelajaran` | Mapel | soft delete, CASCADE saat mapel di-purge |
| Tugas | `tugas` | Mapel | soft delete, CASCADE saat mapel di-purge |
| Lampiran | `lampiran` | **Materi** (`materi_id` NOT NULL) | hard delete + hapus file fisik |
| Pengaturan | `pengaturan` | — | key-value |

### Aturan data

1. **Mapel wajib** untuk catatan, tugas, dan lampiran. Tidak ada data yatim.
2. **Lampiran selalu menempel pada satu materi.** Skema saat ini tidak punya `tugas_id`.
3. Lampiran dari halaman Library (`tambahKeMapel`) masuk ke catatan penampung otomatis berjudul **"Lampiran"** per mapel (`LampiranServiceImpl.judulPenampung`). Catatan itu dibuat sekali, dipakai ulang.
4. File asli **disalin** ke `<app_documents>/lampiran/<microseconds>_<namaAsli>`. DB menyimpan nama asli, path absolut, ukuran byte, tipe (`GAMBAR`/`FILE`).
5. Nama tampilan lampiran boleh di-rename; file di disk tidak di-rename.
6. Satu dialog simpan hanya membawa **satu** lampiran baru (gambar **atau** file), bukan banyak.
7. **Urutan hapus permanen wajib: file fisik dulu, baru baris DB** (`DeleteService`). Kalau dibalik, path file hilang dan file jadi sampah tak terlihat.
8. Soft delete **tidak** menyentuh file fisik. File baru hilang saat purge dari Sampah.
9. Sampah dibersihkan otomatis setelah **30 hari** (`bersihkanSampah`), dan bisa dipulihkan sebelum itu.
10. Judul wajib tidak kosong (`isiWajib: true` di `tanyaTeks`). Deskripsi/isi/tenggat/lampiran opsional.
11. Status tugas hanya `BELUM` / `SELESAI`. `lewatTenggat` dihitung: tenggat < hari ini DAN belum selesai.
12. Semua query daftar hanya menampilkan data aktif (`deleted_at IS NULL`).

### Alur per halaman

**Home**
- Ringkasan angka: belum / selesai / lewat tenggat.
- Seksi: fokus (tenggat ≤7 hari), lewat tenggat, mapel, catatan terbaru.
- Centang tugas langsung dari Home → status `SELESAI`, item dikeluarkan dari daftar, SnackBar **Urungkan** mengembalikan ke `BELUM`.
- Pencarian global menyaring tugas + catatan + mapel di memori (bukan query DB).
- Tidak ada tombol tambah tugas di Home.

**Academic** — 3 tab
- *Mata Pelajaran*: cari, tambah, buka detail, mode seleksi → hapus massal (soft delete ke Sampah).
- *Catatan*: cari (query `cariKata`), tambah (pilih mapel → dialog judul/isi/lampiran), ubah, **ekspor .txt**, hapus permanen. Kartu punya menu `Ubah / Ekspor / Hapus`.
- *Tugas*: filter `Semua / Belum / Selesai`, tambah (pilih mapel → dialog judul/deskripsi/tenggat), ubah, hapus, centang selesai + Urungkan. Kartu punya menu `Ubah / Hapus`.

**Detail Mapel** — 3 tab
- *Materi*: daftar catatan + lembar lampiran (lihat/tambah/rename/hapus) + ekspor.
- *Tugas*: daftar tugas per mapel, filter, tambah/ubah dengan tenggat. Dialog memanggil `denganLampiran: true`, tetapi **hasil lampirannya dibuang** (tidak disimpan) — lihat Fitur B.
- *Info*: ringkasan mapel.

**Library (Penyimpanan)**
- Menampilkan **semua lampiran aktif lintas mapel** lewat join `lampiran → materi → mapel`.
- Statistik: jumlah gambar, jumlah file, total ukuran (dihitung SQL, bukan dari daftar yang dimuat).
- Filter `Semua / Gambar / File`, cari berdasarkan nama file.
- Aksi: buka pakai aplikasi bawaan (`open_filex`), rename, hapus.
- Tambah: pilih sumber (gambar/file) → pilih mapel → otomatis masuk catatan "Lampiran".

**Pengaturan**
- Ganti tema, warna aksen, bahasa (rebuild langsung via `ValueListenableBuilder`).
- Sampah: pulihkan / hapus permanen / bersihkan otomatis.
- Ekspor seluruh data ke satu `.txt`.

### Ekspor
- `eksporSemua`: semua mapel + catatan + tugas + ringkasan, satu file `.txt`.
- `eksporCatatan`: satu catatan + daftar lampiran (nama, jenis, ukuran).
- **Belum ada** `eksporTugas`.

## 2. Fitur A — Samakan tombol kartu Tugas dengan kartu Catatan

Keadaan sekarang (masalah): kartu Catatan punya 3 aksi (`Ubah`, `Ekspor`, `Hapus`). Kartu Tugas hanya 2 (`Ubah`, `Hapus`). Pengguna tidak bisa mengekspor satu tugas.

### Langkah

1. Tambah `eksporTugas(...)` di `lib/services/export_service.dart`, bentuknya mengikuti `eksporCatatan`:
   - header `SYLLABIND — TUGAS`, timestamp;
   - nama mapel, judul, status (`BELUM`/`SELESAI`), tenggat (atau "tanpa tenggat"), deskripsi;
   - daftar lampiran bila Fitur B sudah ada;
   - file `.txt` di `<app_documents>/ekspor/`, pakai `_namaBerkasAman` seperti catatan.
2. Buka akses lewat `lib/services/layanan_ekspor.dart` (`LayananEkspor.eksporTugas`), jangan panggil service langsung dari UI.
3. Di `lib/screen/academic_page.dart` `_TabTugasState`:
   - tambah handler `_eksporTugas(Tugas)` (try/catch → `pesanSukses` / `pesanGagal`);
   - tambah `PopupMenuItem(value: 'ekspor', ...)` dengan ikon `download_outlined`, urutan **Ubah → Ekspor → Hapus** (sama persis dengan catatan);
   - sambungkan di `onSelected`.
4. Samakan juga di `lib/screen/detail_mapel_page.dart` `_TabTugasMapel` supaya perilaku per-mapel tidak beda. (Kalau tidak mau, catat sebagai pengecualian sadar.)
5. Tambah kunci i18n di `lib/tools/bahasa.dart`:
   - `k_ekspor_tugas_tooltip`: "Ekspor tugas (.txt)" / "Export task (.txt)"
   - `dm_ekspor_tugas_sukses`, `dm_ekspor_tugas_gagal`.
   - `k_ekspor_tooltip` yang lama khusus catatan — jangan dipakai ulang untuk tugas.
6. Tes:
   - `test/export`/`data_test`: ekspor tugas menghasilkan file berisi judul, status, tenggat;
   - `ui_test`: menu kartu tugas punya 3 item dan urutannya sama dengan kartu catatan;
   - `i18n_test`: kunci baru ada di kedua bahasa.
7. Perbarui tes klik audit (`audit_klik_test.dart`) kalau menghitung jumlah aksi per kartu.

### Aturan
- Ekspor **tidak** menyalin file lampiran, hanya mencatat nama/jenis/ukuran (konsisten dengan catatan).
- Ekspor hanya data aktif; tugas di Sampah tidak ikut.
- Nama file aman dari karakter `\/:*?"<>|`, maksimal 60 karakter.

## 3. Fitur B — Lampiran tugas muncul di Library

Keadaan sekarang (masalah):
- Skema: `lampiran.materi_id` **NOT NULL** dan FK hanya ke `materi_pembelajaran`. Tugas tidak punya kolom lampiran. Jadi secara data, lampiran tugas **tidak mungkin** ada.
- UI detail mapel: `_TabTugasMapel._tambahTugas` dan `_ubahTugas` sudah memanggil `tanyaTeks(denganLampiran: true)`, tetapi hasil `hasil['lampiran']` **tidak pernah** disimpan (tidak ada panggilan `lampiranRepo.tambahDariFile`). Pengguna memilih gambar/file, melihat nama file di dialog, lalu file itu hilang tanpa pesan.
- Tab Tugas di Academic tidak memakai `denganLampiran` sama sekali.
- Library hanya join ke `materi`, jadi lampiran tugas tidak akan pernah tampil meski barisnya ada.

### Pilihan pendekatan

**Opsi 1 — Migrasi skema (disarankan).** Lampiran bisa dimiliki materi **atau** tugas.
- Benar secara model, tidak mengotori daftar catatan.
- Perlu migrasi v1 → v2 dan penyesuaian semua query + hapus.

**Opsi 2 — Catatan penampung per tugas.** Tiap tugas punya catatan tersembunyi ("Tugas: <judul>") yang menampung lampirannya.
- Tanpa migrasi, cepat.
- Buruk: catatan palsu muncul di tab Catatan/Home/ekspor, judul tugas berubah → catatan yatim, penghapusan tugas tidak ikut membersihkan lampiran.

### Langkah Opsi 1

1. **Skema** (`lib/services/skema_db.dart`)
   - `versi` 1 → 2.
   - `lampiran`: `materi_id` boleh NULL, tambah `tugas_id` boleh NULL, `CHECK` tepat satu pemilik terisi (`materi_id IS NOT NULL` XOR `tugas_id IS NOT NULL`).
   - SQLite tidak bisa mengubah NOT NULL langsung: buat tabel baru → salin baris lama (isi `tugas_id` NULL) → drop tabel lama → rename → buat ulang `idx_lampiran_materi` + `idx_lampiran_tugas`.
   - Tulis `onUpgrade` di `lib/services/db.dart`; jangan andalkan `onCreate` saja.
2. **Model** (`lib/function/lampiran.dart`)
   - `materiId` jadi `int?`, tambah `tugasId`; getter pemilik (`materi`/`tugas`).
   - `toMap`/`fromMap` menyesuaikan. Pertahankan `createdAt`, `ukuran`, `tipe`.
3. **Service** (`lampiran_service.dart` + `_impl`)
   - `tambahKeTugas({tugasId, sumber, tipe})` — salin file seperti `tambahDariFile`, simpan `tugas_id`.
   - `perTugas(int tugasId)`.
   - `semua()`: LEFT JOIN materi **dan** tugas, sertakan lampiran tugas; filter `tugas.deleted_at IS NULL AND mapel.deleted_at IS NULL`.
   - `totalUkuran()` dan `jumlahPerTipe()`: ikutsertakan lampiran tugas (kalau tidak, statistik Library bohong).
   - `hapusFileMilikTugas(int tugasId)` baru.
   - `hapusFileMilikMapel`: file lampiran tugas juga (join `tugas.mapel_id`), bukan hanya lewat materi.
4. **Hapus** (`lib/services/delete_service.dart`)
   - `hapusPermanenTugas`: hapus file fisik **dulu**, baru baris tugas (CASCADE lampiran tugas).
   - `hapusPermanenMapel`: file tugas ikut dihitung sebelum CASCADE.
   - Soft delete tugas tidak menyentuh file; file tetap ada sampai purge.
   - Pastikan lampiran tugas tidak memblokir FK saat tugas dihapus (CASCADE pada `tugas_id`).
5. **UI tambah/ubah tugas**
   - `_TabTugasMapel._tambahTugas`: simpan hasil `tambahKeTugas` setelah `tugasRepo.tambah` mengembalikan id tugas.
   - `_TabTugasMapel._ubahTugas`: dukung tambah lampiran baru (dan tampilkan lampiran yang sudah ada, idealnya lewat lembar seperti `_LembarLampiran`).
   - `_TabTugasState` (Academic): tambahkan `denganLampiran: true` + simpan hasilnya, supaya dua jalur konsisten.
   - Kartu tugas: tampilkan indikator kecil jumlah lampiran (mis. ikon `attach_file` + angka) supaya pengguna tahu file menempel.
6. **Library**
   - Subtitle menampilkan pemilik: `Gambar · 1,4 MB · Tugas: <judul>` atau `· <nama mapel>`.
   - Tambah field/filter opsional `Tugas` (kalau tidak, minimal pastikan item tugas ikut di `Semua`).
   - Rename/hapus/buka tetap jalan tanpa perubahan (semua lewat `lampiran.id`, bukan pemilik).
   - Cari nama file tetap sama.
7. **Ekspor**
   - `eksporTugas` (Fitur A) mencantumkan daftar lampiran tugas.
   - `eksporSemua` boleh menambahkan blok lampiran per tugas; putuskan dan catat.
8. **Tes**
   - migrasi v1 → v2: data lama utuh, `materi_id` masih terisi, `tugas_id` NULL.
   - tambah lampiran ke tugas → muncul di `semua()` Library → statistik naik.
   - hapus permanen tugas → baris lampiran hilang **dan** file fisik terhapus.
   - hapus permanen mapel → file lampiran materi **dan** tugas terhapus.
   - soft delete tugas → lampiran masih ada; restore → masih tampil.
   - lampiran tanpa pemilik / dua pemilik ditolak CHECK.
   - `flutter test` tetap hijau (termasuk golden Library).

### Aturan yang tidak boleh dilanggar
- Satu lampiran tepat satu pemilik (materi XOR tugas).
- File fisik dihapus sebelum baris DB.
- Library tetap satu sumber daftar untuk gambar + file, lintas mapel dan lintas pemilik.
- Statistik Library harus konsisten dengan daftar yang tampil.
- Jangan membuat catatan palsu untuk menampung lampiran tugas (kecuali memilih Opsi 2 secara sadar dan mendokumentasikannya).

4. Perbarui dokumen ini kalau ada keputusan yang berubah.
